## =====================================================================================
## HOW IT WORKS (read once)
## =====================================================================================
##  Browser ──> Streamlit page (ui/app.py, port 8501)
##     │  "Sign in with Cognito"  ──> Cognito hosted login ──> http://localhost:3000/callback
##     │                              (ui/agent_client.py runs that small server on port 3000,
##     │                               swaps the code for tokens, sends you back to the page)
##     └─ each message ──> POST https://bedrock-agentcore.us-east-1.amazonaws.com/runtimes/<RuntimeArn>/invocations
##                          Authorization: Bearer <your access token>  ──> Runtime ──> Gateway ──> Policy ──> Lambda
##
##  Files:
##   ui/app.py            the page: sign-in, chat, sidebar, Yes/No confirmation buttons
##   ui/agent_client.py   Cognito PKCE login, token refresh, calling the Runtime and reading its stream
##   ui/requirements.txt  streamlit + requests (installed on the fly by "uv run --with-requirements")
##   tests/unit/test_ui_client.py   unit tests for agent_client.py (in the repo, not in the .tgz)
##
##  It reads RuntimeArn, ClientId, CognitoDomain and Region from cdk-outputs.json in the project
##  root (written by the deploy). Port 3000 is used because it is the only callback URL the Cognito
##  app client allows (infra/lib/stacks/agentcore-stack.ts).

## =====================================================================================
## TROUBLESHOOTING
## =====================================================================================
##  "localhost refused to connect" on 8501   -> SSH window has no -L 8501 tunnel, or the UI is not running (STEP U2, U3)
##  "localhost refused to connect" on 3000   -> SSH window has no -L 3000 tunnel; reconnect with STEP U2
##  Page says "Port 3000 is busy"            -> cognito-user.py --login is still waiting; run the pkill line of STEP U3, restart
##  "Could not read cdk-outputs.json"        -> run the UI from ~/Banking_support; deploy first if the file is missing
##  "Runtime returned 401/403 ... sign in"   -> token expired or from another deploy: Sign out, sign in again
##  "Runtime returned 424" or a timeout      -> the agent itself failed: check its logs (commands_ec2.txt STEP 7, "aws logs tail ...")
##  Policy denial text in the reply          -> expected: Cedar blocked the tool call (STEP 8)
##  Balances back to the start values        -> normal: demo data lives in Lambda memory (redeploy or cold start resets it)
##
##  NEVER open port 8501 or 3000 in the EC2 security group: the page is only meant to be reached
##  through the SSH tunnel (it listens on localhost only).
